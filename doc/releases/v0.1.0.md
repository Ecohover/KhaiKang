# KhaiKang v0.1.0

This is the first stable MVP release of KhaiKang, an open-source, self-hostable
project and manual test management platform.

## Included

- Project membership, fixed project roles, Issue creation, assignment, status,
  list, board, Markdown content, and evidence attachments.
- Test Workspaces linked to multiple Projects, hierarchical Suites, stable-numbered
  Cases, Tags, Plans, Runs, result recording, and Run completion.
- Stable Test Run snapshots that preserve Case and step content after the source
  Case changes.
- Issue, Test Case, and Test Run Item attachments using UUID storage keys while
  retaining original file names.
- Markdown-based rich content, images, file download dialogs, and read-only rendering.
- Consolidated PostgreSQL baseline migrations and Docker Compose persistent volumes.
- Migration-aware API readiness, end-to-end Web/API health, and automatic
  non-root volume ownership initialization.
- Shared product versioning across the API, Web UI, OCI labels, Git tags, and
  Docker image tags.

## Delivery verification

- Backend and frontend CI passed before the accepted RC images were published.
- Immutable API and Web SHA images passed fresh PostgreSQL, attachment, and
  data-protection volume startup.
- The executable MVP smoke flow passed Project/Issue, two Project-to-Workspace
  links, Case/Plan/Run, all three attachment scopes, attachment SHA-256 checks,
  Test Run snapshots, result completion, and restart persistence.

## Images

```text
ecohover/khaikang-api:0.1.0
ecohover/khaikang-web:0.1.0
```

Use [`deploy/compose/docker-compose.yml`](../../deploy/compose/docker-compose.yml)
with `KHAIKANG_IMAGE_TAG=0.1.0` rather than running either image alone.

## Known limitations

- Backup/restore automation and an isolated restore drill are not bundled yet.
  Back up PostgreSQL, data-protection keys, and attachments as one consistent set
  before hosting data that cannot be recreated.
- The consolidated Initial migrations expect a new PostgreSQL database. Databases
  using earlier development migration history require a separate migration plan.
- Object storage, automated test execution, Playwright orchestration, AI execution,
  and historical security-maintenance branches remain future work.
